# Phase 14 Plan 05: Shared Runtime Polishing & Fixes

**One-liner:** Address UAT observations: enable `general` intent suspension, naturalize completion messages, and refine greedy complaint extraction.

## Goal
Improve the user experience and data quality of the shared agentic runtime by fixing minor design and implementation gaps found during Phase 14 UAT.

## Tasks

### 1. Enable `general` Intent Suspension
- **Issue:** `general` intent currently has `allowSuspend: false`, preventing users from switching to `maid_hire` or `complaint` if they start in a `general` session.
- **Action:** Update `toRuntimePlaybook` in `src/lib/agentic/playbooks.ts` to allow suspension for all intents except perhaps when specifically not desired. Actually, the simplest is to just set it to `true` for all.

### 2. Naturalize Completion Confirmations
- **Issue:** Completion strings for `maid_hire` and `complaint` are instructional placeholders.
- **Action:** Update `RESPONSE_PLAYBOOKS` in `src/lib/responsePlaybooks.ts` with friendly, final responses.

### 3. Refine Greedy Complaint Extraction
- **Issue:** `deriveCallbackPreference` and `deriveIncidentTiming` are too aggressive, capturing the whole message on keywords like "today".
- **Action:** Refine regex logic in `src/lib/agentic/toolRegistry.ts` to return more specific values or only capture when it's clearly a dedicated response.

## Verification Plan

### Automated Tests
- Update `src/test/test-agentic-runtime.ts` with:
    - Test for switching from `general` to `maid_hire`.
    - Test for cleaner `callback_preference` extraction.

### Manual Verification (UAT script)
- Rerun `14-UAT-conversational.ts` and verify:
    - First turn correctly switches if `detectInitialIntent` fails but `runAgenticTurn` catches it.
    - Completion messages look natural.
    - Complaint slots are not redundant.

## Execution Path
1. Modify `src/lib/agentic/playbooks.ts`.
2. Modify `src/lib/responsePlaybooks.ts`.
3. Modify `src/lib/agentic/toolRegistry.ts`.
4. Update and run tests.
