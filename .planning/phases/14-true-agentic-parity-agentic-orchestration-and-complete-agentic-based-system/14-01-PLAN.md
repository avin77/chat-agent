<task>
  <name>Define the shared runtime contract</name>
  <action>
Create shared types for:
- canonical intents
- turn input
- extracted slot candidates
- accepted / rejected slot decisions
- runtime mode (`live_commit`, `shadow_simulate`)
- suspend / resume snapshots
- next-step output

The contract must support side-intent suspension, repair reasoning, and structured comparison between production and shadow.
  </action>
</task>

<task>
  <name>Centralize slot validation and tool policy</name>
  <action>
Move slot-specific save / reject rules into one registry so the same validators are used by live agentic and shadow simulation.

The registry must support:
- required vs optional fields
- reject-with-repair for invalid values
- skip handling only where allowed
- candidate source tracking (regex, llm, user-direct)
  </action>
</task>

<task>
  <name>Define canonical playbooks for supported intents</name>
  <action>
Create runtime playbooks for `maid_hire`, `complaint`, `maid_registration`, and `general` with:
- supported fields
- required vs optional fields
- completion rule
- escalation rule
- answer-first behavior for FAQ cases
- suspend / resume policy

Remove `helper_reg` as a runtime contract name.
  </action>
</task>

<task>
  <name>Introduce shared runtime entrypoint</name>
  <action>
Add a `runAgenticTurn()` entrypoint that receives:
- current intent context
- current session snapshot
- user message
- runtime mode

It should return a structured decision object that downstream handlers can either commit live or log as shadow.
  </action>
</task>
