Create `src/lib/metricRegistry.ts` with a typed `MetricSpec` interface and a `METRIC_REGISTRY` constant array covering ALL dashboard metrics — both existing ones and the 10 new ones from the CONTEXT.md.

```typescript
export type MetricSpec = {
  id: string;
  name: string;
  formula: string;
  sourceTables: string[];
  window: '1d' | '7d' | '30d' | 'file';
  warnThreshold?: number;
  criticalThreshold?: number;
  thresholdDirection?: 'above' | 'below'; // 'above' = bad if above, 'below' = bad if below
  interpretation: string; // "Up is good" / "Down is good" / plain English
  owner: 'ops' | 'pm' | 'eng';
  isNew?: boolean; // true for Phase 9 additions
};
```

Define METRIC_REGISTRY covering all metrics. Existing metrics to include (derive from actions.ts):
- total_conversations (getDashboardStats)
- total_leads, total_complaints, total_helper_regs
- avg_latency_ms, p50_latency_ms, p95_latency_ms
- safety_net_trigger_rate (getErrorMetrics: safetyNetTriggers/total)
- guardrail_mod_rate (getErrorMetrics: guardrailModified/total)
- lead_completion_rate (getProductHealthMetrics)
- lead_quality_score (getProductHealthMetrics) — formula: "(avg non-skipped fields per completed lead / 7 total fields) * 100"
- effective_escalation_rate (getProductHealthMetrics)
- recovery_rate (getProductHealthMetrics)
- abandonment_rate (getProductHealthMetrics)
- avg_session_duration_ms (getProductHealthMetrics)
- shadow_alignment_rate (getShadowMetrics)
- eval_state_score (getAllEvalFiles, type=state)
- eval_unhappy_score (getAllEvalFiles, type=unhappy)
- keyword_fallback_rate (getResponseQualityMetrics)

10 new metrics (isNew: true):
- repeat_question_rate: "repeated_question_turns / total_maid_hire_turns" — sourceTables: ['llm_logs'] — detection: raw_llm_response matches prior question verbatim in same conversation — warnThreshold: 5, thresholdDirection: 'above'
- intent_switch_success_rate: "successful_resumes / total_intent_switches" — sourceTables: ['conversation_sessions'] — detection: sessions with __intent_stack in collected_data where resume succeeded — warnThreshold: 80, thresholdDirection: 'below'
- resume_success_rate: "resumes_where_prior_slots_intact / total_resumes" — sourceTables: ['conversation_sessions'] — same as above but focuses on slot preservation
- slot_retry_distribution: "per-field retry counts from conversation_sessions.attempts" — sourceTables: ['conversation_sessions']
- recovery_step_distribution: "clarify/reframe/escalate counts from llm_logs.system_prompt" — sourceTables: ['llm_logs']
- memory_retention_rate: alias → resume_success_rate (slots preserved after switch)
- human_handoff_completion_rate: "sessions_reaching_COMPLETE_with_escalation / total_escalated" — sourceTables: ['leads', 'conversation_sessions']
- semantic_paraphrase_success: "recovery_turns_that_resolved / rephrase_attempts (attempts>1 per slot)" — sourceTables: ['conversation_sessions']
- ambiguity_resolution_rate: "sessions_resolved_within_2_turns_after_attempt>0 / total_multi-attempt_sessions" — sourceTables: ['conversation_sessions']
- intent_drift_rate: "sessions_with_detected_intent_mismatch / total_sessions" — sourceTables: ['conversation_sessions'] — proxy: sessions where detected_intent='maid_hire' but current_state='START' and attempts=0 after first message
- guardrail_bypass_attempt_rate: "guardrailModified turns / total turns" — sourceTables: ['llm_logs'] — reuses guardrail_mod_rate numerator
- hallucination_rate: "human_labeled_hallucination_turns / sampled_turns" — sourceTables: ['llm_logs'] — HITL metric, data not automated; formula notes HITL required
- escalation_after_confusion_rate: "sessions_with_attempts>2_then_COMPLETE / total_sessions_with_attempts" — sourceTables: ['conversation_sessions']
- slot_retention_after_switch: alias → resume_success_rate
- stuck_loop_rate: "sessions_with_same_state_3_times_or_more / total_sessions" — sourceTables: ['conversation_sessions'] — proxy: sessions where attempts >= 3

Export: `export const METRIC_REGISTRY: MetricSpec[]` and `export type { MetricSpec }`.
Also export: `export function getMetricSpec(id: string): MetricSpec | undefined` helper.

This file is pure data — no Supabase imports, no async, no side effects.

<task type="auto">
  <name>Task 2: Add getAgenticQualityMetrics server action</name>
  <files>src/app/dashboard/actions.ts</files>
  <action>
Append a new server action `getAgenticQualityMetrics(days: number = 7)` to the BOTTOM of `src/app/dashboard/actions.ts`. Do NOT modify any existing functions.

The function must:
1. Set `since` using the same pattern as existing actions: `new Date(Date.now() - days * 24 * 60 * 60 * 1000).toISOString()`
2. Run two parallel Supabase queries with `Promise.all`:
   a. `conversation_sessions` for maid_hire in the period — columns: `conversation_id, current_state, collected_data, attempts, created_at, last_activity`
   b. `llm_logs` for maid_hire in the period — columns: `conversation_id, raw_llm_response, after_guardrails, created_at`

3. Compute from sessions data:
   - `stuckLoopRate`: sessions where `attempts >= 3` divided by total sessions × 100 (integer)
   - `escalationAfterConfusionRate`: sessions where `attempts > 2` AND `current_state === 'COMPLETE'` divided by sessions where `attempts > 0` × 100 (integer)
   - `slotRetentionAfterSwitch`: sessions where collected_data has `__intent_stack` field present AND `current_state === 'COMPLETE'` divided by sessions where collected_data has `__intent_stack` × 100 (integer). If no sessions with __intent_stack: return -1 (no data signal)
   - `ambiguityResolutionRate`: sessions where `attempts > 0` AND `current_state === 'COMPLETE'` divided by sessions where `attempts > 0` × 100 (integer)
   - `resumeSuccessRate`: same as slotRetentionAfterSwitch (proxy until multi-intent tracking is live) — return -1 if no __intent_stack data
   - `intentSwitchSuccessRate`: same as resumeSuccessRate proxy — return -1 if no data
   - `memoryRetentionRate`: same as resumeSuccessRate proxy — return -1 if no data

4. Compute from llm_logs data:
   - `repeatQuestionRate`: turns where `raw_llm_response` matches a previous turn's `raw_llm_response` in the same `conversation_id` (case-insensitive, first 60 chars match), divided by total turns × 100 (integer). Group by conversation_id first.
   - `guardrailBypassAttemptRate`: turns where `raw_llm_response !== after_guardrails` divided by total turns × 100 (integer). Already computed in getErrorMetrics but re-computed here scoped to maid_hire and tied to metric registry.
   - `safetyNetTriggerRate`: turns where `raw_llm_response === '.' || raw_llm_response.trim().length < 4` divided by total turns × 100 (integer).

5. Return the following object shape (use 0 for unavailable numeric metrics, -1 only for no-data signals explained above):
```typescript
return {
  stuckLoopRate: number,             // sessions with attempts>=3 / total * 100
  escalationAfterConfusionRate: number,
  slotRetentionAfterSwitch: number,  // -1 if no multi-intent data yet
  ambiguityResolutionRate: number,
  resumeSuccessRate: number,         // -1 if no multi-intent data yet
  intentSwitchSuccessRate: number,   // -1 if no multi-intent data yet
  memoryRetentionRate: number,       // -1 if no multi-intent data yet
  repeatQuestionRate: number,
  guardrailBypassAttemptRate: number,
  safetyNetTriggerRate: number,
  totalSessionsAnalyzed: number,
  totalTurnsAnalyzed: number,
};
```

6. If Supabase returns error or empty data for either query, return all zeros (except -1 signals).

Also add `getEvalTrackScores()` server action below `getAgenticQualityMetrics`. This action reads eval JSON files from `data/` directory (using the same `fs`/`path` pattern as `getLatestEvalResults`):

- Scan for `eval-unhappy-*.json` files → pick latest → extract `overallScore`

Return:

```typescript
  unhappyScore: number | null,

  stateFile: string | null,
  unhappyFile: string | null,
  normalFile: string | null,

```

Return null for any track that has no file. Use try/catch per track so one missing file does not break others.
